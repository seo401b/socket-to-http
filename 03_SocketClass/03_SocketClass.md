# [Step 3] RAII 기반 TCP 소켓 래퍼 클래스 설계 및 에코 서버·클라이언트 구현

## 1. 개요 (Overview)
* **목표:** 원시적이고 자원 누수 위험이 큰 C 스타일의 소켓 프로그래밍을 극복하기 위해, 현대 C++의 **RAII(Resource Acquisition Is Initialization)** 철학을 녹여낸 나만의 소켓 래퍼 클래스(`TcpSocket`)를 구축하고, 이를 활용해 실시간 에코 서버와 클라이언트를 구현한다.
* **학습 키워드:** RAII 패턴, `socket`, `bind`, `listen`, `connect`, `accept`, `send`, `recv`, TCP 3-way Handshake, 링커 에러(`undefined reference`), 시스템 콜 에러 처리

---

## 2. 핵심 아키텍처 및 동작 원리

### ① RAII 기반 자원 관리와 소멸자 자동화
* **원리:** 소켓 객체가 생성될 때(`constructor`) 운영체제로부터 파일 디스크립터를 할당받고, 객체가 스코프를 벗어나 소멸할 때(`destructor`) 자동으로 `close()`를 호출하여 소켓 자원을 해제한다.
* **효과:** 개발자가 수동으로 `close()`를 호출하지 않아도 소켓 누수(Socket Leak)를 원천 차단할 수 있다.

### ② TCP 연결 수립(`connect`과 `accept`)의 메커니즘
* **클라이언트 (`Connect`):** `inet_pton`을 통해 도메인이나 IP 문자열을 네트워크 바이트 오더의 이진 구조체(`in_addr`)로 변환한 뒤, **`connect()` 시스템 콜**을 호출하여 운영체제 간 TCP 3-way Handshake를 유도한다.
* **서버 (`Bind` & `Accept`):** 특정 포트 번호에 소켓을 고정(`bind`)한 뒤 클라이언트의 연결 요청을 수신 대기(`listen`)하고, 요청이 들어오면 `accept()`를 통해 새로운 통신용 소켓 디스크립터를 할당받아 객체로 캡슐화한다.

## 3. 깊이 있는 개념 정리 (Deep Dive)

### 주소 변환(`inet_pton`)과 실제 연결(`connect`)의 분리
* `inet_pton`은 단순히 주소 문자열을 이진 데이터로 **봉투에 적어두는(구조체 채우기)** 작업일 뿐, 네트워크 선로를 통해 상대방과 통신을 시작하는 행위가 아니다.
* 반드시 `connect()` 시스템 콜이 실행되어야만 커널 레벨에서 TCP 패킷(SYN)이 전송되고 실질적인 세션이 맺어진다.

### 예전 방식(`perror`) vs 모던 C++ 에러 핸들링
* 과거 C언어 스타일의 `perror`는 에러를 콘솔에 무조건 출력하고 제어권이 없어 유연하지 않다.
* 현대 C++에서는 `std::cerr`와 `std::strerror(errno)`를 조합하여 로그 포맷을 통제하거나, `std::system_error` 기반의 예외(Exception)를 던지는 구조가 권장된다.

## 4. 트러블슈팅 노트 (Troubleshooting)

### ① 링커 에러 (`undefined reference to TcpSocket::...`)
* **문제 현상:** 컴파일 시 `testServer.cpp` 내부에서 클래스 선언은 정상 인식되나 `undefined reference` 링크 에러가 발생하며 빌드가 실패함.
* **원인 분석:** 컴파일러에게 `main` 파일만 전달하고, 실제 구현부가 담긴 `TcpSocket.cpp`를 함께 빌드 타겟으로 넘겨주지 않았기 때문.
* **해결 방법:** 컴파일 명령어에 `TcpSocket.cpp`를 명시적으로 추가 (`g++ -std=c++17 main.cpp TcpSocket.cpp -o app`).

### ② 네임스페이스 오타로 인한 컴파일 차단
* **문제 현상:** `std:memset` 구문에서 컴파일 에러 발생.
* **원인 분석:** 콜론(`:`)을 실수로 하나만 입력하여 표준 라이브러리 네임스페이스를 잘못 지정함.
* **해결 방법:** 콜론을 두 개로 수정 (`std::memset`).

### ③ 클라이언트의 즉시 종료 및 연결 수립 누락
* **문제 현상:** 클라이언트가 실행되자마자 에러 코드 반환 없이 곧바로 프로그램이 꺼지거나 서버와 통신이 이루어지지 않음.
* **원인 분석:** `TcpSocket::Connect()` 내부에서 IP 주소 변환(`inet_pton`)만 수행한 뒤 곧바로 `return true;`를 해버려, **실제 TCP 3-way Handshake를 유발하는 `connect()` 시스템 콜이 누락**되어 있었음.
* **해결 방법:** `connect()` 함수를 추가하고 리턴값이 `< 0`인지 검사하여 에러 로그를 출력하도록 수정.

### ④ 버퍼 오염 방지와 `recv_len` 관리
* **문제 현상:** 연속된 데이터 수신 시 이전 턴의 데이터 찌꺼기가 남아 문자열이 깨지는 현상 발생.
* **해결 방법:** 루프 내부에서 매번 `std::memset(buffer, 0, sizeof(buffer))`를 수행하여 메모리 찌꺼기를 원천 차단하고, `std::strlen` 대신 운영체제가 반환한 정확한 바이트 수인 `recv_len`을 기준으로 버퍼 끝에 널 문자(`\0`)를 주입하여 안전한 문자열 포맷 유지.
