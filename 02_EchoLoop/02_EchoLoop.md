# [Step 2] TCP 에코 서버와 지속 통신(Echo Loop) 구현

## 1. 개요 (Overview)
* **목표:** 단발성으로 끝나던 1회용 통신을 확장하여, 연결이 유지되는 동안 실시간으로 데이터를 주고받을 수 있는 **에코 서버(Echo Server)와 클라이언트**를 구현한다.
* **학습 키워드:** `while(1)` 무한 루프, `std::memset` 메모리 초기화, `recv_len` 바이트 관리, TCP FIN 패킷 정상 종료, `std::getline`

## 2. 핵심 아키텍처 및 동작 원리

### ① 에코 루프(Echo Loop)의 흐름
* **현상:** 서버는 클라이언트가 보낸 데이터를 받아 곧바로 다시 돌려주고(`Echo`), 클라이언트가 연결을 끊을 때까지 대기 상태를 유지한다.
* **이유:** 단발성 통신 구조를 무한 루프로 감싸 운영체제 수신 버퍼를 지속적으로 감시함으로써, TCP의 **바이트 스트림(Byte Stream)** 환경에서 연속적인 데이터 수신이 가능해진다.

### ② 메모리 관리와 버퍼 재사용 (`memset`)
* **구현 방식:** 버퍼를 루프 바깥에 선언하고, 매 반복마다 `std::memset(buffer, 0, sizeof(buffer))`를 수행한다.
* **효과:** 이전 턴에 남아있던 데이터 찌꺼기(오버랩)를 원천 차단하고, 메모리를 매번 새로 할당하지 않아 저수준 프로그래밍에서의 안전성과 효율성을 동시에 챙긴다.

## 3. 깊이 있는 개념 정리 (Deep Dive)

### 왜 `std::strlen(buffer)` 대신 `recv_len`을 써야 하는가?
* `std::strlen()`은 널 문자(`\0`)를 기준으로 길이를 세기 때문에, 바이너리 데이터나 예기치 않은 입력 환경에서 실제 읽어온 데이터 크기와 오차가 발생할 수 있다.
* 운영체제가 정확히 읽어낸 바이트 수인 **`recv_len`**을 그대로 `write()`의 크기로 전달하는 것이 가장 안전하다.

### TCP FIN 패킷과 `read()`의 반환값 규칙
* `read()` 함수가 **`0`**을 리턴하는 것은 데이터가 없다는 뜻이 아니라, 상대방이 `close()`를 호출하여 **TCP FIN 패킷**을 보냈음을 의미한다.
* 서버와 클라이언트는 이 `recv_len == 0` 시점을 포착하여 안전하게 `break`로 루프를 탈출하고 소켓을 닫아야 한다.

## 4. 트러블슈팅 노트 (Troubleshooting)

* **문제 현상:** 띄어쓰기가 포함된 문장(`Hello World`)을 입력했을 때, 서버가 단어 단위로 쪼개서 받거나 입력 버퍼가 꼬이는 현상 발생('Hello'만 출력됨).
* **원인 분석:** 클라이언트에서 입력을 받을 때 공백 단위로 첫 단어만 잘라먹는 `std::cin >>` 방식을 사용했기 때문.
* **해결 방법:** 엔터(Newline) 전까지의 모든 문자열을 통째로 읽어오는 **`std::getline(std::cin, input_msg)`**으로 변경하여 문장 단위 통신 보장.
