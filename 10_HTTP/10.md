---------------------------------------
상태 머신 파서

파서 내부의 4가지 상태
(REQUEST_LINE → HEADERS → BODY → COMPLETE)

REQUEST_LINE: 줄 해석
\r\n으로 첫라인을 잡음
공백을 기준으로 문자열 분해하여 request 객체에 담음

HEADERS: 헤더 Key-Value 파싱
\r\n 찾음
라인에 텍스트가 없다면 \r\n\r\n 헤더 끝
헤더 맵에서 Content-Length 값을 조회(바디 크기)
바디 크기가 있다면 BODY상태로
없으면 COMPLETE

BODY: 요청 바디 수신
버퍼 남은 데이터 크기가 바디 크기보다 크다면 request.body에 바디텍스트 담고 상태를 COMPLETE로 변경
만약 바디 크기보다 남은 데이터 크기가 작다면 데이터를 기다림.
기다리는 로직이 다음과 같다.
break로 깨고 나간다음 소켓에 읽기 이벤트 발생을 EPOLLIN으로 기다림
요청 오면 그때 다시 파서 실행됨

COMPLETE: 파싱 완료 및 리셋
파싱된 객체를 out_req에 복사하고 세션상태 초기화
return true로 외부에 알림

-------------------------------------
예시:
POST /login HTTP/1.1\r\n
Host: example.com\r\n
Content-Length: 10\r\n
\r\n
id=admin12

REQUEST_LINE:
POST /login HTTP/1.1  <- \r\n으로 발견
ss >> request.method >> request.path >> request.version;
request.method: POST
request.path: /login
request.version: HTTP 1.1

HEADERS:
Host: example.com  <- \r\n으로 발견
맵에 저장
Content-Length: 10  <- \r\n
맵에 저장
읽어야 할 바디 데이터가 남음

BODY:
더 이상 \r\n 찾지 않음
버퍼의 남은 크기 >= Content-Length조건만 확인
버퍼의 남은 크기가 크다면 id=admin12 BODY 변수에 저장

COMPLETE:
요청이 완료
return true;
다시 REQUEST_LINE으로 초기화
