# [Step 1] TCP 소켓 프로그래밍 뼈대와 기본 개념

## 1. 개요 (Overview)
* **목표:** 운영체제 수준의 소켓(Socket)을 이용해 가장 단순한 형태의 TCP 서버와 클라이언트를 구현하고 통신의 기본 흐름을 이해한다.
* **학습 키워드:** 프로세스 독립성, `socket()`, `sockaddr_in`, `connect()`, `accept()`, 블로킹(Blocking), `ssize_t`

---

## 2. 핵심 아키텍처 및 동작 원리

### ① 프로세스의 독립성과 터미널 실행
* **현상:** 서버와 클라이언트는 컴퓨터 안에서 완전히 별개의 메모리 공간을 사용하는 독립된 프로세스이다.
* **이유:** 서버 프로세스 내부의 `server_addr` 변수에 클라이언트가 직접 접근할 수 없으므로, 클라이언트 역시 자기 자신의 메모리 공간에 접속할 서버의 주소(`server_addr`)를 새로 설정하고 찾아가야 한다.

### ② 소켓 생성 및 주소 설정 (`sockaddr_in`)
* **소켓 생성 (`socket()`):**
  * `AF_INET`: IPv4 인터넷 주소 체계 사용
  * `SOCK_STREAM`: 데이터 유실 없는 신뢰성 있는 TCP 통신 선택
* **주소 구조체 세팅:**
  * `INADDR_ANY`: 내 컴퓨터의 모든 IP에서 접속을 허용 (서버 측)
  * `"127.0.0.1"` (Loopback): 자기 자신을 가리키는 주소 (클라이언트 측)
  * `htons()`: 호스트 바이트 오더를 네트워크 표준 바이트 오더(Big Endian)로 변환

## 3. 깊이 있는 개념 정리 (Deep Dive)

### 📌 왜 `size_t`가 아니라 `ssize_t`를 쓰는가?
* `size_t`는 부호가 없는(unsigned) 타입이라 양수만 다룰 수 있다.
* 하지만 `read()`나 `write()` 같은 시스템 콜은 통신 에러 시 **`-1`**이라는 음수를 반환해야 하므로, 부호가 있는(signed) `ssize_t`를 사용하여 에러 코드를 안전하게 판별한다.

### 📌 블로킹(Blocking)과 시스템 콜의 대기
* `accept()`는 클라이언트가 접속할 때까지, `read()`는 데이터가 도착할 때까지 프로그램이 그 자리에서 멈춰 서서(Blocking) 대기한다.
* 터미널에 아무것도 안 뜨고 멈춘 것처럼 보이는 현상은 프로그램이 다운된 것이 아니라 운영체제 레벨에서 입출력을 열심히 기다리는 정상적인 대기 상태다.

## 4. 트러블슈팅 노트 (Troubleshooting)

* **문제 현상:** 서버를 실행했는데 터미널에 아무런 출력도 뜨지 않고 멈춤.
* **원인 분석:** 
  1. `accept()` 함수가 클라이언트의 접속을 기다리며 블로킹 상태에 걸려 있는 것임.
  2. C++의 `std::cout` 버퍼링 성질 때문에 개행 문자나 버퍼 플러시가 안 되어 화면 출력이 지연될 수 있음.
* **해결 방법:** 클라이언트 창을 별도로 띄워 정상적으로 접속을 시도하거나, 디버깅용 출력문에 `std::endl` 또는 `std::flush`를 활용해 버퍼를 비워줌.
